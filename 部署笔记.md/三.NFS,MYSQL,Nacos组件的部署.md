### 1.网络存储卷NFS

NFS（Network File System）即网络文件系统，是一种分布式文件系统协议。它允许用户通过网络访问远程服务器上的文件，就像访问本地文件一样方便。 NFS 的工作原理是将服务器端的文件系统共享出来，客户端通过网络挂载该共享目录到本地，进行读写。

![image-20261011112016824](C:\Users\xiaobo\AppData\Roaming\Typora\typora-user-images\image-20261011112016824.png)

1.安装NFS服务器，这里用work02节点模拟

```bash
# 安装依赖包
[root@worker02 ~]# dnf install nfs-utils -y

# 编写配置文件
[root@worker02 ~]# mkdir -p /data/nfs
[root@worker02 ~]# cat > /etc/exports << EOF
/data/nfs       *(rw,no_root_squash,sync)
EOF

# 启动服务，配置开机自启
[root@worker02 ~]# systemctl start nfs-server
[root@worker02 ~]# systemctl status nfs-server --no-pager
[root@worker02 ~]# systemctl enable nfs-server
```

2.安装客户端

所有节点安装NFS客户端

```bash
dnf install rpcbind nfs-utils -y
```

**注意**：安装完成后需要启动并开机自启 rpcbind 服务，因为 showmount 命令依赖 RPC 服务获取 NFS 导出列表：

```bash
启动 rpcbind
systemctl start rpcbind && systemctl enable rpcbind
```

3.测试验证

在每个节点上，都要执行以下命令

```bash
showmount -e worker02.itcast.cn    # 改成自己的 NFS 服务器地址，这是查看服务端有哪些可以共享的目录
Export list for worker02.itcast.cn:
/data/nfs *                        # * 代表任何客户端都可以挂载使用这个共享目录
```

最终结果显示，每个节点上，都可以查看挂载

除了 showmount 查看导出列表，还可以直接挂载 NFS 共享目录进行读写验证：

```bash
挂载测试
[root@master01 ~]# mkdir -p /mnt/nfs-test

[root@master01 ~]# mount -t nfs worker02.itcast.cn:/data/nfs /mnt/nfs-test

[root@master01 ~]# echo "test" > /mnt/nfs-test/hello.txt

[root@master01 ~]# cat /mnt/nfs-test/hello.txt
test
[root@master01 ~]# umount /mnt/nfs-test
```

挂载成功、文件读写正常，说明客户端与 NFS 服务器通信畅通

挂载测试建议仅在 master01 节点执行一次即可，其他节点只需确认 showmount 能看到导出列表

```
注意!!
我们这里传统NFS客户端挂载它是手动显式的，也就是说我们需要在NFS服务器上创建共享目录，例如/data/nfs,然后在/etc/exports中配置
/data/nfs       *(rw,no_root_squash,sync)
sudo exportfs -a              # 重新加载 exports 配置，使新规则立即生效
sudo systemctl start nfs-server
sudo systemctl enable nfs-server  # 设置开机自启
还要给这个目录755权限，再在客户端创建空目录作为挂载点，执行mount将服务器的目录挂载到本地挂载目录上，才能进行读写.
mount -t nfs <服务端IP>:/data/nfs /mnt/nfs_client
设置开机自动挂载（可选）
编辑 /etc/fstab，添加一行，这样系统重启后会自动挂载：
<服务端IP>:/srv/nfs/shared  /mnt/nfs_client  nfs  defaults  0 0
=======================================================================
但是！！
在k8s中挂载被自动化了，不需要手动执行挂载操作，创建完目录给完权限就行，pod调度时由kubelet在节点自动准备客户端目录去挂载服务器的目录。
```

##### 3.创建secret配置项

MYSQL_ROOT_PASSWORD 是 root 密码，设置为 Aa123456.

同时预建 nacos 业务用户，供后续 Nacos 连库使用

##### 4.创建ConfigMap配置项

字符集统一 utf8mb4

其中 log-bin=mysql-bin、binlog-format=ROW 开启了 **Binlog（ROW 模式）**

这是 Canal 同步的前提，务必保留：

```bash
cat > /data/jzo2o-single/01-mysql/mysql-configmap.yaml <<'EOF'
# vim mysql-configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: mysql-config
  namespace: jzo2o

    character_set_server=utf8mb4

kubectl describe cm mysql-config -n jzo2o
```

##### 5.创建PV/PVC存储

MySQL 是有状态服务，数据要持久化到 NFS

先创建 **PV**（指向 worker02 的 NFS 共享目录，名称加 -single 后缀，避免与历史多副本部署的旧 PV 冲突）：

```bash
cat > /data/jzo2o-single/01-mysql/mysql-pv.yaml <<'EOF'
apiVersion: v1
kind: PersistentVolume
metadata:
  name: mysql-pv-single
  labels:
    app: mysql
spec:
  capacity:
    storage: 10Gi
  accessModes:
    - ReadWriteOnce
  persistentVolumeReclaimPolicy: Retain
  nfs:
    server: worker02.itcast.cn
    path: /data/nfs/mysql-single
EOF
kubectl apply -f /data/jzo2o-single/01-mysql/mysql-pv.yaml
kubectl get pv
kubectl describe pv mysql-pv-single
```

再创建 **PVC**，与 PV 同名前缀、同大小（10Gi）,务必保留 **selector** **按标签绑定**

同容量的 PV 有多个（nacos/rabbitmq/es 都是 10Gi），无 selector 时 PVC 会随机绑定到别的 PV

```bash
cat > /data/jzo2o-single/01-mysql/mysql-pvc.yaml <<'EOF'
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: mysql-pvc-single
  namespace: jzo2o
spec:
  accessModes:
    - ReadWriteOnce
  # 这里，selector 精确匹配 mysql-pv-single（避免与其他 PV 交叉绑定）
  selector:
    matchLabels:
      app: mysql
  resources:
    requests:
      storage: 10Gi
EOF
kubectl apply -f /data/jzo2o-single/01-mysql/mysql-pvc.yaml
kubectl get pvc -n jzo2o
kubectl describe pvc mysql-pvc-single -n jzo2o
```

##### 6.StatefulSet有状态应用

MySQL 采用 **StatefulSet** 部署（单副本），因为它是强状态服务，需要稳定的网络标识和持久化存储，将 Secret / ConfigMap / PVC 挂载进 Pod：

```bash
cat > /data/jzo2o-single/01-mysql/mysql-statefulset.yaml <<'EOF'
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mysql
  namespace: jzo2o
spec:
  serviceName: mysql
  replicas: 1
  selector:
    matchLabels:
      app: mysql
  template:
    metadata:
      labels:
        app: mysql
    spec:
      containers:
        - name: mysql
          image: swr.cn-north-4.myhuaweicloud.com/ddn-k8s/docker.io/mysql:8.0.26
          imagePullPolicy: IfNotPresent
          resources:
            requests:
              cpu: 250m
              memory: 512Mi
            limits:
              cpu: 1
              memory: 1Gi
          ports:
            - containerPort: 3306
              name: mysql
          env:
            - name: TZ
              value: Asia/Shanghai
            - name: MYSQL_DATABASE
              value: db_nacos_config
          envFrom:
            - secretRef:
                name: mysql-secret
          volumeMounts:
            - name: mysql-config
              mountPath: /etc/mysql/conf.d/my.cnf
              subPath: my.cnf
            - name: mysql-data
              mountPath: /var/lib/mysql
      volumes:
        - name: mysql-config
          configMap:
            name: mysql-config
        - name: mysql-data
          persistentVolumeClaim:
            claimName: mysql-pvc-single
EOF
kubectl apply -f /data/jzo2o-single/01-mysql/mysql-statefulset.yaml
kubectl get sts -n jzo2o
kubectl get pods -n jzo2o -w
```

**说明**：MYSQL_DATABASE 环境变量会自动创建 db_nacos_config 库

```Bash
echo 'U2VjcmV0S2V5MDEyMzQ1Njc4OTAxMjM0NTY3ODkwMTIzNDU2Nzg5MDEyMzQ1Njc4OTAxMjM0NTY3ODkw' | base64 -d
#这是一段编码，可以改成自己的，用openssl生成一个就行openssl rand -base64 64或者用自己的强密码再手动编码echo -n '你的强密码123!@#' | base64
这段 Base64 编码（NACOS_AUTH_TOKEN）是 Nacos 服务端用来签发和校验身份令牌（Token）的密钥，它本身不是一个让你手动输入的密码，而是服务端和客户端之间自动完成鉴权用的。你可以把它理解为 Nacos 的“总钥匙”：

服务端：Nacos 启动时加载这个密钥，之后所有客户端来访问时，Nacos 用它来签发一个 Token 给客户端，并校验客户端后续请求带来的 Token 是否合法。

客户端：微服务（比如 jzo2o-orders）连接 Nacos 时，会自动用这个密钥去“换”一个 Token，之后每次请求都带着这个 Token。整个过程是代码自动完成的，不需要人工输入密码。
```

###### 服务实例启动后的顺序

```properties
服务实例启动
   │
   ▼
① 读本地 bootstrap.yml（Nacos 地址、用户名、密码）
   │
   ▼
② 向 Nacos 登录 ──带上 username/password──▶ Nacos
   │                                          │
   │                          校验 users 表，用 NACOS_AUTH_TOKEN 签发 JWT
   │                                          │
   │◀──────────── 返回 JWT Token ─────────────┘
   │
   ▼
③ 带着 Token 做后续所有事：
   ├─ 注册服务实例（IP、端口）
   ├─ 拉取自己的配置
   └─ 定期发心跳

#客户端注册时的鉴权流程
客户端带用户名/密码来登录
微服务启动时，配置里写了 username: nacos / password: nacos。它先向 Nacos 发一个登录请求，带上这对用户名密码。

Nacos 校验用户名密码
Nacos 查 users 表，比对密码（BCrypt 校验）。校验通过后，用 NACOS_AUTH_TOKEN 作为密钥，签发一个 JWT Token 返回给客户端。

客户端拿到 Token，带着它去注册
客户端把 Token 存在本地内存，之后每次请求（包括注册服务、拉配置、发心跳）都带上这个 Token。

Nacos 每次请求都校验 Token
Nacos 用同一个密钥验证 Token 是否合法、是否过期。合法就放行，否则拒绝。
```

##### 7.部署Service服务

Nacos 需要两个端口暴露：

8848 是配置中心 API（NodePort 30848，供微服务连接）

8080 是控制台（NodePort 30080/30081，供浏览器访问，根路径需登录 nacos/nacos）

```bash
cat > /data/jzo2o-single/02-nacos/nacos-service.yaml <<'EOF'
apiVersion: v1
kind: Service
metadata:
  name: nacos
  namespace: jzo2o
spec:
  type: NodePort
  selector:
    app: nacos
  ports:
    - name: http
      port: 8848
      targetPort: 8848
      nodePort: 30848
    - name: console
      port: 8080
      targetPort: 8080
      nodePort: 30081
EOF
kubectl apply -f /data/jzo2o-single/02-nacos/nacos-service.yaml
kubectl get svc -n jzo2o
kubectl describe svc nacos -n jzo2o | grep -A2 Endpoints
```
