**面试话术 - 为什么网关最后部署**：

```properties
在微服务架构中，网关是所有外部请求的统一入口。如果网关先启动，而下游服务还没注册上来，这时候访问网关就会返回 502。所以标准的部署顺序是：先部署基础服务（foundations），再部署业务服务（publics、customer、market、orders、trade 等），最后部署网关。这是"依赖先就绪"原则。

网关**不自己记 IP**,而是通过**服务注册中心(Nacos)**找到服务:`lb://publics` 表示"从注册中心找叫 publics 的服务,负载均衡挑一个实例转发"。流程是 **服务启动时注册自己 → 网关转发时问 Nacos 要实例列表 → 负载均衡选一个 → 转发到该实例的 IP:端口**。这套叫**服务注册与发现**。注意它和 k8s Service 是**两层**机制:前者是应用层(Nacos),后者是基础设施层(k8s),在你项目里配合工作。
```

### 3.辅助组件 - Sentinel Dashboard的部署

**Sentinel**（阿里巴巴开源）是面向分布式服务架构的**流量控制、熔断降级**组件，与 Hystrix、Resilience4j 同属微服务的"护城河"组件，但更强调**实时监控**与**规则热更新**。

Sentinel 本身以轻量级客户端的形式嵌入微服务运行；**Dashboard** 则是配套的可视化控制台（独立 Web 应用），用于配置流控 / 降级规则、查看实时监控数据

先掌握以下几个核心概念，就能看懂 Dashboard 上的所有配置：

- **资源（Resource）**：被 Sentinel 保护的入口，例如一个 HTTP 接口或一段业务代码，用唯一名称标识。
- **规则（Rule）**：施加在资源上的保护策略，主要包括**流量控制**（按 QPS / 并发线程数限流）、**熔断降级**（异常比例 / 异常数 / 平均响应时间超过阈值后快速失败）、**系统保护**（入口整体负载兜底）。
- **客户端（Client）**：随微服务运行，在本地采集指标并执行规则，同时把指标**上报**给 Dashboard。
- **控制台（Dashboard）**：独立的可视化应用，展示实时监控、支持在线修改规则并推送生效。

```yaml
spring:
  cloud:
    sentinel:
      transport:
        dashboard: sentinel-dashboard:8858  # 指向Dashboard
        port: 8719                          # 客户端监听端口
      eager: true                           # 服务启动即建立心跳
```
