# 四.RabbitMQ,ES,Canal,redis组件的部署

### 1.RabbitMQ部署

RabbitMQ 是微服务之间的异步消息中间件，用于实现服务的解耦/异步，业务要写发消息代码，与Canal不同，Canal实现的是数据同步，依靠的是MySQL Binlog,对业务无侵入。

##### 1.创建NFS目录

单节点 **Deployment** 部署，配置与数据持久化到 NFS，在 worker02 上创建数据目录：

```bash
[root@worker02 nfs]# mkdir -p /data/nfs/rabbitmq-single && chmod 777 /data/nfs/rabbitmq-single
[root@worker02 nfs]# ls
mysql-single  nacos-single  rabbitmq-single
```

##### 2.创建yaml文件目录

```bash
mkdir -p /data/jzo2o-single/03-rabbitmq && cd $_
```

##### 3.创建ConfigMap配置项

| 配置项/文件      | 作用说明                                                     |
| :--------------- | :----------------------------------------------------------- |
| enabled_plugins  | 开启管理台插件                                               |
| rabbitmq.conf    | 设置管理员账号并指定 management.load_definitions 从 JSON 导入业务账号 |
| definitions.json | 预置业务账号 xzb/xzb（vhost /xzb）+ 交换机 exchange.canal-jzo2o |

```bash
cat > /data/jzo2o-single/03-rabbitmq/rabbitmq-config.yaml <<'EOF'
apiVersion: v1
kind: ConfigMap
metadata:
  name: rabbitmq-config
  namespace: jzo2o
data:
  enabled_plugins: |
    [rabbitmq_management, rabbitmq_shovel, rabbitmq_shovel_management].
  rabbitmq.conf: |
    loopback_users = none
    default_user = admin
    default_pass = Aa123456.
    default_vhost = /
    management.load_definitions = /etc/rabbitmq/definitions.json
  definitions.json: |
    {
      "users": [
        { "name": "xzb", "password": "xzb", "tags": "" },
        { "name": "czri", "password": "czri1234", "tags": "administrator" }
      ],
      "vhosts": [
        { "name": "/" },
        { "name": "/xzb" }
      ],
      "permissions": [
        { "user": "xzb", "vhost": "/xzb", "configure": ".*", "write": ".*", "read": ".*" },
        { "user": "czri", "vhost": "/", "configure": ".*", "write": ".*", "read": ".*" },
        { "user": "czri", "vhost": "/xzb", "configure": ".*", "write": ".*", "read": ".*" }
      ],
      "parameters": [],
      "policies": [],
      "queues": [],
      "exchanges": [
        {
          "name": "exchange.canal-jzo2o",
          "vhost": "/xzb",
          "type": "topic",
          "durable": true,
          "auto_delete": false,
          "internal": false,
          "arguments": {}
        }
      ],
      "bindings": []
    }
EOF
kubectl apply -f /data/jzo2o-single/03-rabbitmq/rabbitmq-config.yaml
```

##### 5.创建Deployment无状态应用

单节点 RabbitMQ 用 **Deployment** 部署，把 ConfigMap 三个文件挂到 /etc/rabbitmq，PVC 挂到 /var/lib/rabbitmq：

```bash
cat > /data/jzo2o-single/03-rabbitmq/rabbitmq-deployment.yaml <<'EOF'
apiVersion: apps/v1
kind: Deployment
metadata:
  name: rabbitmq
  namespace: jzo2o
spec:
  replicas: 1
  selector:
    matchLabels:
      app: rabbitmq
  template:
    metadata:
      labels:
        app: rabbitmq
    spec:
      containers:
        - name: rabbitmq
          image: docker.io/library/rabbitmq:3.13-management
          imagePullPolicy: IfNotPresent
          resources:
            requests:
              cpu: 100m
              memory: 256Mi
            limits:
              cpu: 500m
              memory: 512Mi
          ports:
            - name: amqp
              containerPort: 5672
            - name: management
              containerPort: 15672
          env:
            - name: RABBITMQ_DEFAULT_USER
              value: admin
            - name: RABBITMQ_DEFAULT_PASS
              value: Aa123456.
          readinessProbe:
            tcpSocket:
              port: 5672
            initialDelaySeconds: 60
            periodSeconds: 20
            timeoutSeconds: 5
            failureThreshold: 6
          livenessProbe:
            tcpSocket:
              port: 5672
            initialDelaySeconds: 180
            periodSeconds: 20
            timeoutSeconds: 5
            failureThreshold: 3
          volumeMounts:
            - name: config
              mountPath: /etc/rabbitmq
            - name: data
              mountPath: /var/lib/rabbitmq
      volumes:
        - name: config
          configMap:
            name: rabbitmq-config
        - name: data
          persistentVolumeClaim:
            claimName: rabbitmq-pvc-single
EOF
kubectl apply -f /data/jzo2o-single/03-rabbitmq/rabbitmq-deployment.yaml
```

**说明**：RabbitMQ 初始化较慢（约 3 分钟），

liveness 探针 initialDelaySeconds: 180 是为避免慢启动被误杀；

readiness 探针 60 秒后开始探测，确保就绪状态真实。

##### 5.创建Deployment无状态应用

ES 需要 vm.max_map_count 内核参数（否则启动报 max virtual memory areas vm.max_map_count [65530] is too low），用 **initContainer**（privileged）在 Pod 所在节点上设置；

数据目录 UID 1000 通过 NFS 目录 777 权限解决。

若 Pod 仍报 AccessDenied node.lock，在 worker02 上执行 chown -R 1000:1000 /data/nfs/es-single

```bash
cat > /data/jzo2o-single/05-elasticsearch/es-deployment.yaml <<'EOF'
apiVersion: apps/v1
kind: Deployment
metadata:
  name: es
  namespace: jzo2o
spec:
  replicas: 1
  selector:
    matchLabels:
      app: es
  template:
    metadata:
      labels:
        app: es
    spec:
      initContainers:
        - name: set-vm-max-map-count
          image: docker.io/library/busybox:1.36
          command: ["sysctl", "-w", "vm.max_map_count=262144"]
          securityContext:
            privileged: true

      containers:
        - name: es
          image: docker.io/library/elasticsearch:8.15.3
          imagePullPolicy: IfNotPresent
          ports:
            - containerPort: 9200
              name: http
            - containerPort: 9300
              name: transport
          env:
            - name: ES_JAVA_OPTS
              value: "-Xms512m -Xmx512m"
            - name: discovery.type
              value: "single-node"
          resources:
            requests:
              cpu: 500m
              memory: 512Mi
            limits:
              cpu: "1"
              memory: 1Gi
          volumeMounts:
            - name: es-config
              mountPath: /usr/share/elasticsearch/config/elasticsearch.yml
              subPath: elasticsearch.yml
            - name: es-data
              mountPath: /usr/share/elasticsearch/data
      volumes:
        - name: es-config
          configMap:
            name: es-config
        - name: es-data
          persistentVolumeClaim:
            claimName: es-pvc-single
EOF
kubectl apply -f /data/jzo2o-single/05-elasticsearch/es-deployment.yaml
```

### 3.Canal部署

Canal 订阅 MySQL 的 Binlog，把变更数据投递到 RabbitMQ（微服务消费后同步到 ES）

单节点 **Deployment** 部署，配置与运行时数据持久化到 NFS，先在 worker02 上创建数据目录：

##### 1.创建NFS目录

```bash
[root@worker02 nfs]# mkdir -p /data/nfs/canal-single && chmod 777 /data/nfs/canal-single
[root@worker02 nfs]# ls
canal-single  es-single  mysql-single  nacos-single  rabbitmq-single
```

##### 2.创建canal数据库用户（关键）

Canal 要读取 MySQL Binlog，必须有一个具备复制权限的账号

**两个坑务必注意**：

- MySQL 8 默认认证插件是 caching_sha2_password，而 Canal 1.1.5 内置的 otter 驱动**不支持**它，连接时报 caching_sha2_password Auth failed——必须显式指定 mysql_native_password
- 授权用 REPLICATION SLAVE, REPLICATION CLIENT（读取 binlog 的最小权限）

```bash
# 在 MySQL（mysql-0）里创建 canal 用户并授权
[root@master01 ~]# kubectl exec -it mysql-0 -n jzo2o -- sh
mysql -uroot -pAa123456.
mysql> CREATE USER IF NOT EXISTS 'canal'@'%' IDENTIFIED WITH mysql_native_password BY 'Aa123456.';
Query OK, 0 rows affected (0.01 sec)

mysql> GRANT SELECT, REPLICATION SLAVE, REPLICATION CLIENT ON *.* TO 'canal'@'%';
Query OK, 0 rows affected (0.00 sec)

mysql> FLUSH PRIVILEGES;
Query OK, 0 rows affected (0.01 sec)

# 验证（plugin 必须是 mysql_native_password）
mysql> SELECT user, host, plugin FROM mysql.user WHERE user='canal';
+-------+------+-----------------------+
| user  | host | plugin                |
+-------+------+-----------------------+
| canal | %    | mysql_native_password |
+-------+------+-----------------------+
1 row in set (0.00 sec)
```

##### 3.ConfigMap配置项

Canal 需要两部分配置：

1. canal.properties（全局：RabbitMQ 投递目标 + destination 名）
2. instance.properties（实例：MySQL 连接与监听表）

关键点：

1. canal.serverMode = rabbitMQ 指定投递到 RabbitMQ
2. rabbitmq.* 指向 RabbitMQ（vhost /xzb、账号 xzb、topic 交换机 exchange.canal-jzo2o）

```bash
cat > /data/jzo2o-single/06-canal/canal-config.yaml <<'EOF'
apiVersion: v1
kind: ConfigMap
metadata:
  name: canal-config
  namespace: jzo2o
data:
  canal.properties: |
    canal.port = 11111
    canal.metrics.pull.port = 11112
    canal.serverMode = rabbitMQ
    canal.file.data.dir = ${canal.conf.dir}
    canal.destinations = xzb-canal
    canal.conf.dir = ../conf
    canal.auto.scan = true
    canal.auto.scan.interval = 5
    canal.mq.flatMessage = true
    rabbitmq.host = rabbitmq
    rabbitmq.virtual.host = /xzb
    rabbitmq.exchange = exchange.canal-jzo2o
    rabbitmq.username = xzb
    rabbitmq.password = xzb
    rabbitmq.deliveryMode = 2

  instance.properties: |
    canal.instance.mysql.slaveId=1000
    canal.instance.gtidon=false
    canal.instance.master.address=mysql:3306
    canal.instance.master.journal.name=mysql-bin.000001
    canal.instance.master.position=0
    canal.instance.dbUsername=canal
    canal.instance.dbPassword=Aa123456.
    canal.instance.connectionCharset=UTF-8
    canal.instance.enableDruid=false
    canal.instance.filter.regex=jzo2o-orders\\.orders_dispatch,jzo2o-orders\\.orders_seize,jzo2o-foundations\\.serve_sync,jzo2o-customer\\.serve_provider_sync,jzo2o-orders\\.serve_provider_sync,jzo2o-orders\\.history_orders_sync,jzo2o-orders\\.history_orders_serve_sync,jzo2o-market\\.activity
    canal.mq.dynamicTopic=canal-mq-jzo2o-orders-dispatch:jzo2o-orders\\.orders_dispatch,canal-mq-jzo2o-orders-seize:jzo2o-orders\\.orders_seize,canal-mq-jzo2o-foundations:jzo2o-foundations\\.serve_sync,canal-mq-jzo2o-customer-provider:jzo2o-customer\\.serve_provider_sync,canal-mq-jzo2o-orders-provider:jzo2o-orders\\.serve_provider_sync,canal-mq-jzo2o-orders-serve-history:jzo2o-orders\\.history_orders_serve_sync,canal-mq-jzo2o-orders-history:jzo2o-orders\\.history_orders_sync,canal-mq-jzo2o-market-resource:jzo2o-market\\.activity
    canal.mq.partition=0
EOF
kubectl apply -f /data/jzo2o-single/06-canal/canal-config.yaml
```

##### 5. Deployment 无状态应用

Canal 镜像内的 conf 目录是不可写的，需要一个 **initContainer** 把镜像自带 conf 复制到 PVC，再写入我们的 canal.properties / instance.properties（按 destination 名 xzb-canal 分目录），主容器启动时挂载该 PVC 到 /home/admin/canal-server/conf：

```bash
cat > /data/jzo2o-single/06-canal/canal-deployment.yaml <<'EOF'
apiVersion: v1
kind: Service
metadata:
  name: canal
  namespace: jzo2o
spec:
  type: NodePort
  selector:
    app: canal
  ports:
    - name: tcp
      port: 11111
      targetPort: 11111
      nodePort: 31111
    - name: metrics
      port: 11112
      targetPort: 11112
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: canal
  namespace: jzo2o
spec:
  replicas: 1
  selector:
    matchLabels:
      app: canal
  template:
    metadata:
      labels:
        app: canal
    spec:
      initContainers:
        - name: init-canal-config
          image: docker.io/canal/canal-server:v1.1.5
          imagePullPolicy: IfNotPresent
          command:
            - sh
            - -c
            - |
              set -e
              cp -a /home/admin/canal-server/conf/. /work/conf/
              rm -rf /work/conf/example
              mkdir -p /work/conf/xzb-canal
              cp /config/canal.properties /work/conf/canal.properties
              cp /config/instance.properties /work/conf/xzb-canal/instance.properties
              chmod -R u+rwX,go+rX /work/conf
          volumeMounts:
            - name: canal-config
              mountPath: /config
            - name: canal-conf-work
              mountPath: /work/conf
      containers:
        - name: canal
          image: docker.io/canal/canal-server:v1.1.5
          imagePullPolicy: IfNotPresent
          ports:
            - containerPort: 11111
              name: tcp
            - containerPort: 11112
              name: metrics
          resources:
            requests:
              cpu: 250m
              memory: 256Mi
            limits:
              cpu: "1"
              memory: 512Mi
          volumeMounts:
            - name: canal-conf-work
              mountPath: /home/admin/canal-server/conf
      volumes:
        - name: canal-config
          configMap:
            name: canal-config
            items:
              - key: canal.properties
                path: canal.properties
              - key: instance.properties
                path: instance.properties
        - name: canal-conf-work
          persistentVolumeClaim:
            claimName: canal-pvc-single
EOF
kubectl apply -f /data/jzo2o-single/06-canal/canal-deployment.yaml
```

### 4.redis部署

Redis 是微服务的基础依赖，在部署微服务之前必须先部署好。课程 Nacos 共享配置约定的 Redis 密码是 redis

##### 1.创建NFS目录

```bash
# 在 NFS 服务器 worker02 上创建 Redis 数据目录
[root@worker02 nfs]# mkdir -p /data/nfs/redis-single && chmod 777 /data/nfs/redis-single

[root@worker02 nfs]# ls
canal-single  es-single  mysql-single  nacos-single  rabbitmq-single  redis-single
```

##### 2.创建yaml文件目录

```bash
mkdir -p /data/jzo2o-single/02-redis && cd $_
```

##### 3.ConfigMap配置项

以 ConfigMap 保存 Redis 配置并挂载为容器内的 /etc/redis/redis.conf，其中 requirepass redis 设置了访问密码：

```bash
cat > /data/jzo2o-single/02-redis/redis-config.yaml <<'EOF'
apiVersion: v1
kind: ConfigMap
metadata:
  name: redis-config
  namespace: jzo2o
data:
  redis.conf: |
    bind 0.0.0.0
    protected-mode no
    port 6379
    requirepass redis
    appendonly yes
    dir /data
EOF
kubectl apply -f /data/jzo2o-single/02-redis/redis-config.yaml
```

##### 4.PV/PVC

1.先创建 **PV**（指向 worker02 的 NFS 共享目录）：

```bash
cat > /data/jzo2o-single/02-redis/redis-pv.yaml <<'EOF'
apiVersion: v1
kind: PersistentVolume
metadata:
  name: redis-pv-single
  labels:
    app: redis
spec:
  capacity:
    storage: 2Gi
  accessModes:
    - ReadWriteOnce
  persistentVolumeReclaimPolicy: Retain
  nfs:
    server: worker02.itcast.cn
    path: /data/nfs/redis-single
EOF
kubectl apply -f /data/jzo2o-single/02-redis/redis-pv.yaml
```

2.再创建 **PVC**，通过 selector 精确匹配 redis-pv-single 的 app: redis 标签（避免与同容量的 canal PV 交叉绑定）：

```bash
cat > /data/jzo2o-single/02-redis/redis-pvc.yaml <<'EOF'
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: redis-pvc-single
  namespace: jzo2o
spec:
  accessModes:
    - ReadWriteOnce
  # selector 精确匹配 redis-pv-single（避免与同容量的 canal PV 交叉绑定）
  selector:
    matchLabels:
      app: redis
  resources:
    requests:
      storage: 2Gi
EOF
kubectl apply -f /data/jzo2o-single/02-redis/redis-pvc.yaml
```

##### 5.Deployment 无状态应用

单节点交付版 Redis 用 **Deployment** 部署（单副本；数据落在 NFS PV，Pod 重建不丢数据）。

Service 提供集群内访问名 redis，并对外暴露 NodePort **30379** 便于调试；

Deployment 挂载上一步的 redis-pvc-single：

```bash
cat > /data/jzo2o-single/02-redis/redis.yaml <<'EOF'
apiVersion: v1
kind: Service
metadata:
  name: redis
  namespace: jzo2o
spec:
  type: NodePort
  selector:
    app: redis
  ports:
    - name: redis
      port: 6379
      targetPort: 6379
      nodePort: 30379
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: redis
  namespace: jzo2o
spec:
  replicas: 1
  selector:
    matchLabels:
      app: redis
  template:
    metadata:
      labels:
        app: redis
    spec:
      containers:
        - name: redis
          image: redis:7.2.7
          imagePullPolicy: IfNotPresent
          resources:
            requests:
              cpu: 50m
              memory: 64Mi
            limits:
              cpu: 200m
              memory: 256Mi
          command: [redis-server, /etc/redis/redis.conf]
          ports:
            - containerPort: 6379
          volumeMounts:
            - name: redis-data
              mountPath: /data
            - name: redis-config
              mountPath: /etc/redis/redis.conf
              subPath: redis.conf
      volumes:
        - name: redis-config
          configMap:
            name: redis-config
        - name: redis-data
          persistentVolumeClaim:
            claimName: redis-pvc-single
EOF
kubectl apply -f /data/jzo2o-single/02-redis/redis.yaml
```
